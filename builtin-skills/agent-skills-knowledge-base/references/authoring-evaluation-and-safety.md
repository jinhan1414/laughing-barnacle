# Skill 编写、评估与安全

编写 Skill 的核心原则：
- Anthropic 官方工程实践强调：默认假设模型已经很强，只补充它不知道、且值得占用上下文的内容。
- 优先写真正可复用的流程知识，而不是把普通常识重复塞进 Skill。
- 当某段逻辑需要确定性或重复执行时，优先放进 `scripts/`，而不是反复让模型即席生成。

编写流程建议：
1. 先明确要覆盖的真实使用场景。
2. 找出哪些步骤每次都会重复。
3. 把稳定流程写进 `SKILL.md`。
4. 把大块参考材料拆到 `references/`。
5. 把需要可靠执行的动作收敛到 `scripts/`。

评估口径：
- Anthropic 官方强调从真实任务与可观察结果中迭代 Skill。
- 若需要总结为一句话，可以说：
  - “先用真实任务验证，再根据失败模式调整 Skill 内容与资源组织。”

安全边界：
- Skill 本身可能引导模型执行脚本、调用工具、读取外部资源，因此只能信任可信来源。
- Skill 不应隐式扩大权限边界。
- 若 Skill 涉及执行动作、密钥或高风险资源，必须把边界写清楚，而不是让模型自由猜测。

何时不该抽 Skill：
- 若只是一次性提示，没必要强行抽成 Skill。
- 若逻辑没有复用价值，或者不比普通 Prompt 更稳定，也没必要抽成 Skill。
- 这是基于官方工程实践的归纳，不是硬性协议条款。
