# 资料选择与写法

选资料时优先这样排：
1. 官方规范或版本页
2. 官方文档
3. 官方 SDK / 官方仓库
4. 本仓库代码与测试
5. 只有在前面都不足时，才补次级来源

适合做知识库型 Skill 的主题特征：
- 资料来源清楚，能找到权威入口
- 用户会反复问
- 回答时需要稳定口径
- 需要区分“标准”“产品实践”“本仓库实现”

写 `SKILL.md` 时的推荐句式：
- “若用户问的是通用协议，优先使用……”
- “若用户问的是本仓库现状，优先使用……”
- “若问题混合了标准与现状，先讲标准，再讲本项目当前实现。”
- “需要核对版本时，先读……”

写 `references/*.md` 时的推荐方式：
- 每个文件只解决一类问题。
- 用短句列出事实、优先级、回答口径。
- 可以包含链接、代码路径、接口路径，但不要堆砌长段原文。

知识库型 Skill 最常见的错误：
- 只收集资料，没有定义“回答框架”。
- 没有把“标准”和“本仓库现状”分开。
- 引用的事实会变，但正文没有给版本入口。
- 主题拆分不清，导致 reference 文件重复和互相覆盖。
- 没有补测试，后续无法确保 Skill 可索引和可读。

默认测试清单：
- Skill 能出现在 `ListEnabledSkillIndex`
- `ReadEnabledSkillPrompt` 能读取主正文
- 关键 reference 文件存在
- 主正文包含权威入口和 reference 路径提示
